# MakerShelf 프론트엔드

React + TypeScript + Vite + Tailwind CSS + shadcn/ui. 프로젝트 전체 개요는 [루트 README](../README.md)를 참고하세요.

## 처음 실행하기

### 1. Node.js 설치 확인

Vite 최신 버전 기준으로 **Node 20.19 이상, 또는 22.12 이상**이 필요해요 (그 사이 버전은 안 돼요). `winget`/`brew`로 설치하면 보통 최신 LTS가 깔려서 문제없지만, 버전을 꼭 확인하세요.

**Windows (PowerShell)**

```powershell
winget install OpenJS.NodeJS.LTS
node --version   # v20.19 이상 또는 v22.12 이상이어야 함
```

**macOS**

```bash
brew install node
node --version
```

`node`가 인식되지 않으면 PowerShell(또는 터미널)을 껐다 다시 켠 뒤 다시 확인하세요. 그래도 안 되면 오류 메시지 전체와 함께 리더에게 문의하세요.

### 2. 의존성 설치

```bash
cd frontend
npm install
```

### 3. 개발 서버 실행

```bash
npm run dev
```

실행 후 터미널에 뜨는 `Local` 주소(보통 `http://localhost:5173`)를 브라우저에서 열면 됩니다.

## 폴더 구조

- `src/App.tsx` — 최상위 컴포넌트
- `src/components/ui/` — shadcn/ui로 생성된 컴포넌트
- `src/lib/utils.ts` — `cn()` 등 공용 유틸
- `@/*` 경로는 `src/*`를 가리킵니다 (`vite.config.ts`, `tsconfig.json` 설정)

## shadcn/ui 컴포넌트 추가하기

```bash
npx shadcn@latest add <component-name>
```

## 프론트엔드 작업 정리 (메인 페이지)

### 담당 작업: 메인(인덱스) 페이지 프론트엔드

**사용 기술**: React 19, TypeScript, Vite, Tailwind CSS v4, shadcn/ui(Radix), react-router-dom, lucide-react

#### 1. 메인 페이지 구성 (4개 섹션)
- **Hero**: 서비스 소개 문구와 스크롤 안내
- **Roles**: 역할 카드 3장. 스크롤할수록 한 장씩 순서대로 나타나는 연출
- **Features**: 주요 기능 소개
- **CTA**: 행동 유도 영역과 Footer

#### 2. 프레젠테이션식 스크롤 (`usePresentationController`)
- 휠, 터치, 키보드 입력을 직접 받아 섹션 단위로 넘어가게 만들었습니다.
- 첫 화면에서 스크롤하면 다음 섹션으로 부드럽게 넘어갑니다. 이동 곡선은 easeOutExpo를 직접 구현했습니다.
- Roles 섹션에서는 화면을 고정하고, 스크롤 양만큼 카드를 펼치거나 접습니다.
- Features 이후는 일반 스크롤로 돌아가고, 다시 올라오면 Roles 위치에 자연스럽게 맞춰집니다.
- 트랙패드 관성 때문에 카드가 한꺼번에 열리는 문제를 쿨다운으로 막았습니다.
- 다른 요소와 충돌하지 않게 했습니다.
  - 입력창이나 드롭다운에 포커스가 있으면 방향키를 가로채지 않습니다.
  - 메뉴 목록 안에서는 메뉴 자체 스크롤이 동작합니다.

#### 3. 리퀴드 글래스 UI (`LiquidGlass`, `GlassFilters`)
- 유리 질감 컴포넌트를 직접 만들었습니다. 층은 배경 블러, SVG 렌즈 왜곡(`feDisplacementMap`), 색조, 하이라이트 순으로 쌓았습니다.
- 네비바, 사이드메뉴, 카드에서 공통으로 사용합니다.

#### 4. 반응형 네비게이션 바
- 화면 너비에 따라 4단계로 바뀝니다.
  - **1400px 이상**: 전체 표시
  - **1100px 이상**: 검색창 대신 아이콘. 누르면 검색창이 펼쳐집니다.
  - **883px 이상**: 검색과 계정 아이콘만 표시. 펼치면 로고가 밀려납니다.
  - **882px 이하**: 메뉴 버튼만 표시
- 다른 곳을 클릭하거나 Esc를 누르면 펼친 항목이 닫힙니다.

#### 5. 사이드 메뉴
- 넓은 화면에서는 네비바 옆에서 펼쳐지는 패널입니다.
- 740px 이하에서는 전체화면 메뉴로 바뀝니다.
  - 로고가 메뉴 안으로 옮겨집니다.
  - 메뉴가 열린 동안 뒤 페이지는 스크롤되지 않습니다.
- 882px 이하에서는 검색, 언어 전환, 로그인/회원가입 버튼을 메뉴 안으로 옮겼습니다.
- 화면 높이가 낮으면 메뉴 목록만 스크롤됩니다. 위아래 끝은 그라데이션 마스크로 자연스럽게 사라지게 했습니다.

#### 6. 공통 컴포넌트와 기능
- **SearchField**: 네비바와 메뉴가 함께 쓰는 검색창입니다. 입력하면 지우기(X) 버튼과 검색 버튼이 나타납니다.
- **다국어(한/영)**: Context로 언어를 관리하고, 선택한 언어는 localStorage에 저장합니다.
- **404 페이지**: 없는 주소로 들어오면 안내 화면을 보여줍니다.
- **접근성**: 아이콘 버튼에 aria-label을 달았고, 키보드로도 조작할 수 있습니다.

#### 7. 코드 리뷰 반영 (PR #6)
- 375px 모바일에서 가로 스크롤이 생기지 않는 것을 확인했습니다.
- 섹션 높이를 `100svh`로 바꿔 모바일 주소창 문제를 해결했습니다.
- 링크 안에 버튼이 중첩된 구조를 고치고, 쓰지 않는 컴포넌트를 정리했습니다.

### 배운 점
- **브라우저 렌더링 원리**: 부모에 `opacity`나 `mask-image`가 걸리면 자식의 `backdrop-filter`(블러)가 사라진다는 것을 알게 됐습니다. 애니메이션 방식을 바꿔 해결하면서, 화면이 레이어 단위로 그려진다는 걸 이해했습니다.
- **CSS 우선순위**: Tailwind 유틸리티보다 layer 밖에 작성한 CSS가 우선한다는 것을 배웠습니다. 스타일이 예상대로 적용되지 않을 때 원인을 찾는 법을 익혔습니다.
- **스크롤 직접 제어의 어려움**: 휠, 트랙패드 관성, 터치, 키보드는 입력 특성이 모두 다릅니다. 이걸 하나의 흐름으로 묶으면서 이벤트 처리와 상태 관리(`useRef`, `preventDefault`)를 깊이 다뤘습니다.
- **반응형 설계**: 단순히 크기만 줄이는 것으로는 부족했습니다. 화면 크기마다 어떤 요소를 어디로 옮길지 정하는 것이 반응형 설계라는 것을 배웠습니다.
- **코드 리뷰 협업**: 리뷰에서 접근성, 모바일 대응, 시맨틱 구조처럼 혼자서는 놓친 부분을 짚어줬고, PR 코멘트로 반영 내역을 공유하는 흐름을 경험했습니다.

### 느낀 점
- 디자인 시안을 그대로 옮기는 것보다, 화면 크기와 입력 방식이 다양한 실제 환경에서 자연스럽게 동작하게 만드는 데 훨씬 많은 시간이 들었습니다.
- 메뉴가 열릴 때 유리 효과가 잠깐 사라지거나 끝부분이 선처럼 잘리는 작은 어색함을 고치면서, 사용자가 느끼는 완성도는 세부에서 나온다는 것을 실감했습니다.
- 처음에는 화려한 효과에 집중했지만, 리뷰를 거치며 누구나 쓸 수 있는 화면(접근성)과 유지보수하기 쉬운 구조도 그만큼 중요하다는 것을 알게 됐습니다.
